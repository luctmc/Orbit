# F-163 — Ausência de host de plugins do aplicativo
status: aberto
severidade: baixa

- Causa raiz: catálogo de skills/plugins das CLIs não é um runtime de extensões do aplicativo.
- Correção: API Orbit 1 explicitamente experimental, manifesto estrito e permissões/grants persistentes por hash; alteração de fonte desativa autorização. Host de painéis de texto, comandos locais ao plugin e eventos de status sanitizados, em Web Worker terminável dentro de iframe opaco sandbox=allow-scripts. CSP bloqueia rede, recursos, frames e formulários. Sem Node/DOM/Tauri no código do plugin; sem capacidades de filesystem, shell, serviços, pagamentos ou provedores. Revogação desmonta imediatamente a execução local e persiste o grant desativado.
- Limites reais: runtime de plugins ligado ao painel aberto, não é host Node nem compatibilidade automática Orca/CLI. Browser controla memória/processos; sem promessa de heap quota/isolamento OS universal. Fila 16, prazo 2 s, mensagens 100/s e payloads limitados; worker encerrado em falha/prazo, sem retry. Não instala/roda terceiros: jornadas usam fixture própria em dados temporários.
- Validação: appPlugins/sandbox 4/4 (permissões, source hash, restart/revogação, links/traversal, script escape). Chromium e WebKit confirmaram ausência de Node/DOM/rede, eventos mínimos, revogação e loop infinito terminado mantendo core responsivo. Typecheck e suíte completa 363 sidecar +49 frontend passaram antes da revisão final. Jornadas e capturas em docs/plans/2026-10-18-six-improvements/.
- API/atribuição: PLUGIN_API.md e THIRD_PARTY_NOTICES.md; fontes Orca bbdbe72 fixadas com MIT e hashes.
- (resolvedor) Correção: integração final/instalação pendentes; permanece aberto até entrega.

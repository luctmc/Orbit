# F-165 — Atualização GitHub falha na ponte do motor persistente
status: feito
severidade: alta

- Reprodução: Orbit 0.2.31, atualização informa `Could not fetch a valid release JSON from the remote`, apesar de a release GitHub conter manifesto e arquivo assinado íntegros.
- Causa raiz: o plugin Tauri autentica com `x-orbit-token`; a ponte aceitava somente Bearer/query. Mesmo se autenticada, não traduzia o header para o token privado do daemon e devolvia URLs do daemon, incompatíveis com o token da janela. O timeout de 15 s da ponte também era menor que o prazo de download pelo gh.
- Correção: traduzir o header apenas na fronteira da ponte, reescrever URLs de arquivos para a ponte atual e permitir o prazo do gh. Não altera chaves, credenciais ou ciclo de vida dos terminais.
- Vermelho: teste HTTP real com startServer + startRuntimeBridge retornou 401 em vez de 200; log em docs/analysis/2026-10-18-github-updater/red.log.
- Verde: regressão de manifesto, arquivo, assinatura preservada, 204/401/403/405/502; runtimeDaemon confirma PTYs preservados. Typecheck global. Ponte dev contra daemon instalado e GitHub real: manifesto/arquivo 200, arquivo 46.661.953 bytes com hash igual ao GitHub e assinatura Ed25519/minisign e comentário autenticado válidos; 2 terminais mantidos.
- (resolvedor) Correção: 45f86ab, packages/sidecar/src/runtimeDaemon.ts e packages/sidecar/test/updates.test.ts. Ponte rejeitava o header do plugin e expunha URLs do daemon sem traduzir os tokens. Regressão red→green, typecheck global, 377 testes sidecar + 50 UI, manifesto/arquivo reais com hash e assinatura válidos; app nativo local recompilado/instalado consultou GitHub sem erro (native-bootstrap.txt). Integração/Official release/instalação oficial são gates separados, acompanhados no recibo final; o build local de bootstrap já está instalado.
